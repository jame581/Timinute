# v2.5 Server-side Timer, Timer Notifications, Aurora Dialogs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the running timer from one browser tab's `sessionStorage` to the server. Then add long-running and idle warnings through a working topbar bell, with opt-in browser notifications. Finally, replace the Radzen Material dialogs with Aurora-native ones.

**Architecture:** A new `RunningTimer` table (one row per user, PK `UserId`) behind a `TimerAppService` and a `TimerController`. Stopping the timer converts the row into a normal `TrackedTask` through the existing `TimeEntryAppService.LogAsync`, inside one DB transaction. On the client, a `TimerService` owns timer state, and a `TimerNotificationService` derives the bell items from that state, the user's preferences and a JS idle detector. An `AuroraDialogService` plus an `<AuroraDialogHost>` replace Radzen's `DialogService`.

**Tech Stack:** .NET 10, ASP.NET Core, EF Core 10 (SQL Server; SQLite and InMemory in tests), Blazor WASM, xUnit + Moq, bUnit, `TimeProvider` (`Microsoft.Extensions.TimeProvider.Testing` → `FakeTimeProvider` in tests).

**Spec:** `docs/superpowers/specs/2026-11-14-v2.5-timer-notifications-design.md`

## Global Constraints

- **Branch and PR flow:** branches are named `feature/<name>`; PRs target `develop`. Commits and PRs carry **no AI traces** (no Co-Authored-By, footers or session links). The commit author is `jame581 <21112138+jame581@users.noreply.github.com>`.
- **Four PRs, in this order:**
  - PR A: Tasks 1–4, `feature/v2.5-timer-notifications` (the branch that already holds the spec and this plan)
  - PR B: Tasks 5–7, `feature/v2.5-notification-bell`
  - PR C: Tasks 8–9, `feature/v2.5-aurora-dialogs`
  - PR D: Task 10, the release
- **Ownership:** every new endpoint is scoped to `User.FindFirstValue(Constants.Claims.UserId)` and has no route ids. A client `ProjectId` is whitespace→`null` and `Trim()`ed, and must belong to the caller.
- **Dates:** all dates are `DateTimeOffset` UTC. Seed SQLite tests with `TimeSpan.Zero` offsets only. Client display uses `.ToLocalTime()`.
- **Status codes:** validation errors return 422 `application/problem+json`. Conflicts return 409, and a missing timer returns 404.
- **Preference defaults:** `LongTimerWarningHours` is `decimal(4,1)`, default `8.0`, range 0–24, and `0` means off. `IdleWarningMinutes` is `int`, default `15`, range 0–240, and `0` means off.
- **Stop rules:**
  - `EndAt` must satisfy `StartDate < EndAt <= UtcNow + 5s`.
  - A duration under 1 s is clamped to 1 s.
  - A timer name is required, trimmed, with a max length equal to `TrackedTask.Name`'s.
- **Browser opt-in:** `localStorage` key `timinute.notifications.browser` (`"1"`/absent). Notification `tag` = `"{rule}:{timer StartDate ticks}"`.
- **Client polling:** `GET /Timer` on start, every 60 s while visible, and on focus or visibility change. The notification check loop runs every 30 s.
- **UI:** Aurora tokens only. No new Radzen visual components and no Bootstrap. Keep `color-scheme` on `:root` / `[data-theme="dark"]`.
- **Reviewers before each PR:** `ef-repository-reviewer` for server tasks and `aurora-client-reviewer` for client tasks.
- **Client services:** register with `AddScoped`, like `UserProfileService` (in WASM that is app lifetime). `AnalyticsService` stays a singleton; nothing here touches it.

## Review Focus

1. **Two tabs press Start within the same second.** Exactly one timer is created, and the loser gets 409 instead of a 500 from the PK violation. → Task 2 test `Start_ConcurrentInsert_PkViolation_Maps_To_Conflict`.
2. **A project deleted (soft) while its timer runs.** Stop still succeeds, the task is saved without a project, and `ProjectCleared` is true. → Task 2 test `Stop_ProjectSoftDeletedMidRun_SavesWithoutProject`.
3. **The user is upgraded mid-session, with a v2.4 `trackedTask` still in sessionStorage.** Its placeholder gets the real end time and nothing is lost or duplicated. → Task 4 test `Legacy_SessionTimer_IsStoppedOnce_AndKeyRemoved`.
4. **The device clock is minutes off from the server.** Elapsed time and the idle "Stop at" stay sane: `EndAt` before the start is rejected with 422, never saved. The client computes elapsed time from the server's `StartDate` and corrects with the `Date` header offset. → Task 2 test `Stop_EndAtBeforeStart_Returns422`, Task 4 test `Elapsed_UsesServerClockOffset`.
5. **The browser denies notification permission or doesn't support it.** The toggle reverts, a hint is shown, and the bell keeps working. → Task 7 test `BrowserToggle_PermissionDenied_RevertsAndShowsHint`.
